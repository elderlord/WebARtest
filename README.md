# WebAR 전시패널 텍스트 강조 — 0단계 계측 하네스

전시패널(재인쇄 없음)을 폰 카메라로 비추면 본문 속 특정 단어에 시각 효과를 거는
WebAR 프로젝트의 **0단계(거리·타겟 실측)** 스캐폴드다.

> 이 저장소는 아직 **효과를 구현하지 않는다.** 문서 §9.2 지침대로, 0단계가
> 통과되기 전에는 1단계(일렁임/글로우) 효과로 넘어가지 않는다. 지금 목적은
> "관람 거리에서 인식되는가 / 근접 시 정합 오차가 글자 크기 이내인가"를
> 가장 싸게 판별하는 것이다.

## 무엇을 하는가

- 8th Wall **Image Targets**(MIT) + three.js로 카메라 뷰를 띄운다.
- 이미지 타겟이 인식되면, 효과 대신 **정합 확인용 와이어프레임 박스**를 타겟에 부착한다.
  인쇄 패널의 실제 테두리와 이 가상 박스가 얼마나 겹치는지가 곧 정합 오차다.
- HUD에 0단계 측정 항목을 실시간 노출한다:
  - **인식 상태** (지시등) — 이 등이 꺼지는 지점이 "인식 성공 최대 거리/기울기"
  - **거리(cm)** — 카메라~타겟
  - **기울기(°)** — 정면=0
  - **지터(mm)** — 정지 상태 위치 표준편차

## 실행

```bash
npm install
npm run dev      # https://<PC-IP>:5173 — 같은 Wi-Fi의 폰에서 접속
```

- 카메라 접근은 HTTPS(보안 컨텍스트)에서만 된다. dev 서버는 자체 서명 인증서를 쓰므로
  폰 브라우저에서 인증서 경고를 한 번 수락한다.
- **인앱 브라우저 주의**(문서 §6): 카카오톡·인스타그램 등 인앱 웹뷰는 카메라를 막는다.
  QR 옆에 "Safari/Chrome으로 열기" 안내가 필요하다.

### DEV 모드 vs AR 모드

앱은 부팅 시 self-host XR8 런타임(`/xr8/xr8.js`)을 찾는다.

| 조건 | 동작 |
|---|---|
| 런타임 **없음** (현재) | **DEV 모드** — 모의 씬으로 three.js·HUD가 실기기에서 뜨는지만 점검 |
| 런타임 **있음** + 컴파일 타겟 | **AR 모드** — 실제 이미지 타겟 인식 + 정합 박스 |

즉 **패널 사진이 없는 지금도** `npm run dev`로 셸을 폰에서 확인할 수 있다.

## 구조

```
src/
  main.js            부트스트랩 (런타임 감지 → AR/DEV 분기)
  hud.js             0단계 계측 HUD
  style.css
  ar/
    xr8.js           8th Wall 파이프라인 + 이미지 타겟 모듈 (AR 경로)
    alignmentBox.js  정합 확인용 와이어프레임 박스 (효과 아님, 계측용 자)
    metrics.js       거리·기울기·지터 계산
  dev/
    mockScene.js     DEV 모드 모의 씬
public/
  xr8/               ← self-host XR8 런타임 슬롯 (README 참고)
  targets/           ← 컴파일된 이미지 타겟 슬롯 (README 참고)
```

## 착수 시 채워야 할 두 슬롯 (오프라인 미확정)

0단계 실측을 실제로 돌리려면 두 가지가 필요하다. 현재 오프라인에서 확정하지 못해
슬롯으로 비워 두었다:

1. **`public/xr8/` — self-host XR8 런타임.** 8th Wall 클라우드 종료로 과거의
   `apps.8thwall.com/xrweb` 로드가 불가하다. 오픈소스 엔진 빌드 또는 데스크톱 앱
   export 산출물을 벤더링해야 한다. → `public/xr8/README.md`
2. **`public/targets/` — 컴파일된 이미지 타겟.** 패널 정면 사진 → `image-target-cli`
   컴파일. 사진 미확보 상태라 아직 없다. → `public/targets/README.md`
   - 타겟 준비 후 `src/ar/xr8.js`의 `IMAGE_TARGET_NAME`을 실제 이름으로 교체.

### three.js 버전 주의

8th Wall 엔진은 three.js와 버전 결합이 있다. 런타임을 확정한 뒤 `package.json`의
`three` 버전을 XR8 번들이 기대하는 버전에 맞춰 핀 고정할 것. (현재 `^0.160.0`은
안전 기준값이며 실 런타임 확인 후 조정)

## 0단계 측정 프로토콜 (문서 §5)

실제 전시장 조명 아래, 관람객이 서는 위치에서 측정한다.

| 항목 | 읽는 법 |
|---|---|
| 인식 성공 최대 거리 | 뒤로 물러나며 지시등이 꺼지는 거리(HUD 거리값) 기록 |
| 최대 기울기 각도 | 비스듬히 기울여 인식이 끊기는 각도(HUD 기울기값) 기록 |
| 근접 시 정합 오차 | 근접 상태에서 와이어프레임 테두리가 패널 테두리에서 벗어난 양 |
| 정지 상태 지터 폭 | 폰 고정 후 HUD 지터값 |

**성공 기준**: 관람 거리에서 인식 + 근접 시 오차가 대상 글자 높이의 절반 이내.

> §2 확인 결과 강조 대상이 **제목급 큰 글자**로 좁혀져, 근접 요구가 줄고 정합 여유가
> 커졌다 — 0단계 통과 가능성이 한 단계 높아진 상태다.

**실패 시**(문서 §5): 강조 단위 확대(단어→문단/박스) → 제목급 글자 한정 →
대상 패널 교체 순으로 후퇴.
